# Design decisions

Key design decisions in guardrail-gw, each with the reasoning and what it would cost if it turned out wrong.
Format: what, why, and the cost if wrong.

- Go standard library plus one dependency (`go.yaml.in/yaml/v3`); no fsnotify, no Prometheus client — fewer moving parts and a reviewable supply chain for a security component — cost if wrong: the hand-written metrics registry lacks summaries/exemplars and would need replacing for a real deployment.
- streaming exactness is guaranteed by a per-detector contract (bounded MaxLen, declared alphabet, local decisions) instead of a fixed hold-back window — a fixed window either leaks long secrets or delays every token; the contract gives exactness with a hold-back of roughly one partial word on prose — cost if wrong: a detector that violates the contract silently breaks exactness; mitigated by deriving MaxLen/alphabet from the regex syntax tree, rejecting anchors/unbounded repeats, the property test, the fuzz target and `make mutation`.
- regexes may not use `^ $ \b \B`; boundaries are checked in Go with explicit left context — a scan resumed mid-text must decide exactly like a full scan — cost if wrong: slightly more code per detector.
- overlapping findings are merged into their union and labeled by strongest action then priority — redacting only the "winning" span can leak the edges of a longer overlapping secret — cost if wrong: occasionally wider redactions and labels that differ from a human's (e.g. the held-out `github_token` exact-match result).
- a streamed block ends the choice with `finish_reason: content_filter` after the safe prefix, not an HTTP error — headers are already sent; SDKs understand content_filter — cost if wrong: clients that ignore finish_reason may show a truncated answer as complete.
- buffered responses use the same truncate-on-block semantics as streams — one behavior to document and test; the HTTP-level property test compares the two paths — cost if wrong: some operators may prefer a 5xx for buffered blocks.
- placeholders are typed and numbered per exchange (`[EMAIL_1]`), shared between request and response, and never reversed — readable for the model and humans; irreversibility removes any de-anonymization oracle — cost if wrong: apps that need the original values back in responses must handle it themselves (roadmap: opt-in reversible mode).
- ambiguous bare numbers (unseparated SSN/Aadhaar, 10–11 digit phones without separators) require a nearby keyword; NANP numbers with separators must be grouped 3-3-4 — kills false positives on IDs, order numbers and IBAN tails seen on the dev split — cost if wrong: misses unformatted numbers in prose without context and fictional numbers like `(800) 123-4567` (invalid NANP exchange).
- one national-ID scheme per country for US, IN, ES, CN (SSN, Aadhaar/Verhoeff, DNI-NIE/mod-23, RIC/MOD 11-2) — the goal is checksummed national IDs; these four cover three different checksum families plus a structural-only one — cost if wrong: other countries' IDs are not detected.
- SSNs are validated structurally (area/group/serial rules) because they carry no checksum — the target is national IDs with checksums; SSN is included as the realistic US case and documented as structural — cost if wrong: higher false-positive risk than checksummed IDs, mitigated by the dashed-or-keyword rule.
- IBAN detection is uppercase only with a 47-country length table — lowercase IBANs are rare and admitting them would double candidate scanning on prose — cost if wrong: misses lowercase IBANs.
- `=` is not part of the entropy-token alphabet — otherwise `KEY=value` forms one run and the redaction swallows the variable name (found on dev) — cost if wrong: base64 padding is left outside the redacted span (harmless).
- secrets longer than detector bounds (entropy runs > 512 B, credential values > 64 B) are not reported rather than truncated — reporting a prefix would leak the suffix while claiming success — cost if wrong: long secrets pass undetected (documented limitation).
- the credential-assignment detector reports only the value, keeping the key name visible — `password: [CREDENTIAL_ASSIGNMENT_1]` keeps the prompt meaningful — cost if wrong: none observed.
- request defaults are PII=redact, secret=block; response defaults PII=redact, secret=redact — a prompt containing a credential is almost always a mistake worth stopping; a response containing one is better cleaned than cut — cost if wrong: operators may want response secrets blocked (one config line; the demo shows it).
- injection scoring covers `user` and `tool` messages only — system/assistant turns are authored by the application; tool output is the indirect-injection vector — cost if wrong: injected text the app copies into a system message is not scored.
- injection threshold 0.70 — best F1 on the dev split sweep (0.65 and 0.70 tied; the higher threshold was chosen to favor precision) — cost if wrong: held-out recall 0.898; lowering to 0.60 trades precision (dev precision drops to 0.887).
- entropy `min_bits` 4.0 — dev precision/recall were flat from 3.5 to 4.0; the highest value with full dev recall was kept to limit false positives on real text — cost if wrong: may miss low-entropy random tokens.
- held-out errors were inspected only after the held-out numbers in README were recorded, and the two injection failure modes found (lone persona phrase; spaced letters after a quote) were documented, not fixed — fixing them would make the held-out number optimistic — cost if wrong: a known normalizer gap ships; it is listed under Limitations and Roadmap.
- the PEM-body template line was changed from a fixed string to a labeled `{high_entropy_token}` in both splits before any held-out evaluation — the fixed string was an unlabeled secret that the detector correctly flagged — cost if wrong: none; disclosed here for transparency.
- config reload by polling content hash (default 2 s) plus SIGHUP, not fsnotify — works with atomic-rename editors and ConfigMaps on every OS with no dependency — cost if wrong: up to one interval of delay.
- `listen` and `audit.path` are not hot-reloadable — rebinding sockets or forking an audit chain mid-flight is riskier than a restart — cost if wrong: a restart is required for those two keys (logged as a warning).
- the upstream timeout bounds the whole exchange, including streaming — simple and prevents stuck streams — cost if wrong: very long generations need a larger timeout.
- upstream non-200 bodies are relayed (bounded) without filtering — they describe failures, and rewriting them hampers debugging — cost if wrong: an upstream that echoes the prompt in an error could leak already-redacted-by-us text only (requests are redacted before forwarding), so exposure is limited to request-side `log`-action values.
- audit HMAC key from an env var; without it a random per-process key is used and a warning logged — never write raw values, never ship a default key — cost if wrong: digests are not comparable across restarts until the key is configured.
- audit appends are not fsynced — per-request fsync would dominate latency — cost if wrong: the last records can be lost on power failure (the chain stays verifiable).
- rate limiting is a per-key token bucket on requests, not tokens — request counts are known before calling upstream; token accounting needs usage data that streams may omit — cost if wrong: one expensive request costs the same as a cheap one.
- the fake upstream is shipped as an internal package (not test-only) — the demo and the benchmark use it, so `make demo`/`make bench` need no model — cost if wrong: none.
- benchmarks run upstream, gateway and load generator in one process on loopback — reproducible on any laptop with one command — cost if wrong: absolute numbers understate network/TLS costs; README says so.
- coverage is gated on `internal/` (core logic) measured across all tests with `-coverpkg=./internal/...` — `cmd/` packages are thin wiring exercised by their own tests — cost if wrong: cmd/ code coverage is not gated.
- `make check` runs tests with `-race -short` and the coverage run without `-short` — the race detector multiplies property-test cost; the full case counts still run once per check — cost if wrong: races that only appear in the long property runs would be missed (those tests are single-goroutine).
- the "integration" target is `make demo-ollama` (real local model, skips cleanly when absent) instead of Docker — the upstream is Ollama on the host; no container is needed — cost if wrong: none for this project.
