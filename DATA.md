# Data

## Synthetic evaluation corpus (committed)

| File | Rows | Seed | Content |
|---|---:|---:|---|
| `testdata/corpus/detection-dev.jsonl` | 1,500 | 101 | text + gold spans (`start`, `end`, `kind`) — tuning split |
| `testdata/corpus/detection-heldout.jsonl` | 1,500 | 202 | same schema — reporting split |
| `testdata/corpus/injection-dev.jsonl` | 600 | 303 | text + label (1 = injection attempt) — tuning split |
| `testdata/corpus/injection-heldout.jsonl` | 600 | 404 | same schema — reporting split |

- **Source:** generated by this repository (`internal/corpus`, `cmd/corpusgen`,
  regenerate with `make corpus`). Generation is deterministic; a test
  (`cmd/corpusgen`) fails if the committed files drift from the generator.
- **License:** MIT, same as the code.
- **Size:** about 0.9 MB total.
- **Construction:** sentences are filled from templates whose slots are
  either a detector kind (labeled positive) or a hard negative (dates, IPs,
  versions, order numbers, ISBNs, UUIDs, git SHAs, prices, identifiers, and
  checksum-*invalid* cards, IBANs, SSNs and Aadhaar numbers). The dev and
  held-out splits use **disjoint template lists** and **disjoint name/domain
  vocabularies**; values are regenerated per split with different seeds.
  Injection prompts combine attack phrasings (dev and held-out lists are
  disjoint) with benign carriers ("summarize this email: ...") and benign
  prompts that contain trigger words ("make git ignore previously committed
  files").
- **No real personal data.** Every value is random and only satisfies format
  and checksum rules; names come from small fixed lists; domains are
  `example`-style or fictional.
- **Known bias:** the same author wrote templates, generators and detectors,
  so format coverage is aligned by construction. Treat the scores as an
  implementation-correctness measure, not as real-world accuracy.

## Fixed sample values used in tests and the demo

- `AKIAIOSFODNN7EXAMPLE` and `wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY`: AWS
  documentation example credentials (public, non-functional).
- `4111 1111 1111 1111`, `5555555555554444`, `378282246310005`-style numbers:
  widely published payment test card numbers.
- `GB82WEST12345698765432`, `DE89370400440532013000`: the standard IBAN
  examples from the IBAN registry documentation.
- `11010519491231002X`: a commonly published PRC RIC checksum example.
- The JWT in `internal/detect/detect_test.go` is the jwt.io sample token.

No external datasets are downloaded by any script.
